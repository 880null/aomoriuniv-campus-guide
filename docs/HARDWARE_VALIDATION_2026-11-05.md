# 実機接続の確認（2026-11-05）

MacにUSB接続したUno互換基板を検出し、Arduino CLIでも`arduino:avr:uno`として認識した。基板写真はELEGOO UNO R3。接続先は`/dev/cu.usbmodem1101`。

ユーザー確認で、実配線はD2〜D6の5本、レストラン棟はLED未実装と判明した。設定は1号館D2、3号館D3、5号館D4、6号館D5、7号館D6。4号館・レストラン棟はpin=nullで実機命令を送らず、情報表示とシミュレーションは維持する。D7・D8は出力として初期化しない。

## ソフトウェアと基板で確認できたこと

- 旧プログラムのフラッシュをローカル一時フォルダーへ読み出して保存した。バックアップと回路写真は公開リポジトリへ含めない。
- 通信識別子を`READY:CAMPUS:4`に統一。旧版v1〜v3は接続成功として扱わない。
- DOM結合テスト3件が成功。実機モードでC/Hの選択が点灯命令を送らないことも確認した。
- Python自動テスト65件が成功。未実装C/Hの命令拒否、旧v3の拒否、未使用D7/D8を変更しない模擬ファームウェア検査を含む。
- Arduino IDEと共通のスケッチをUno向けにビルドし、接続中の基板へ書き込んだ。Arduino AVR Boards 1.8.8、プログラム2448 / 32256 bytes、RAM 206 / 2048 bytes。
- 更新後のWebアプリで実機接続、C/HのHTTP 400、A/B/D/E/Fの点灯命令と状態応答、最後の全消灯を確認した。[実行結果JSON](hardware-results/2026-11-05-v4.json)を参照。

## 目視確認と未確認事項

途中の6施設用テストでは、ユーザーから一部不点灯の報告があった。その後「6号館・7号館が光らない」「使用ピンは2〜6」「レストラン棟は未実装」と共有され、配線を見直した状態で5施設用v4へ更新して再テストした。

最終テスト後、ユーザーから「無事光った」「回路の接続が悪かっただけだった」と報告され、5施設の点灯を目視確認できた。発光はユーザーの目視報告、通信応答はツールで確認した結果として区別する。ArduinoのACKとSTATEはプログラム内の状態応答であり、LEDの発光・電圧・導通の測定結果ではない。写真でも接触状態・内部の導通・抵抗値までは断定していない。WindowsでのUSB接続、実機の抜去・再接続、外部回路の電圧測定は未確認。

## 今回の起動方法

OneDrive内の`.venv`でFlaskの読み込みが長時間待ちになったため、ソースと依存関係を同期対象外のローカル一時フォルダーへ用意して起動した。元のプロジェクトと仮想環境は保持している。起動中のWebアプリは`http://127.0.0.1:5050/`、実機モード。
